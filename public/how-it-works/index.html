HOW IT WORKS

AI can reason.
Deterministic code owns the veto.

AI can interpret intent and explain outcomes. CIRCUIT keeps the final financial decision inside deterministic, typed controls.

01

FINANCIAL MANDATE

Define the operating envelope.

The user activates versioned constraints for products, assets, order size, daily spend, concentration, drawdown, evidence freshness, and behavior limits.

→
02

POLICY ENGINE

Check hard rules first.

Typed policy checks validate authorization, product and asset scope, caps, budgets, concentration, drawdown, evidence freshness, and uncertain settlement.

→
03

RUNTIME DRIFT

Evaluate behavior over time.

Sequence-aware supervision detects semantic retries, order-frequency anomalies, sticky pause states, and market-regime changes that a per-request check can miss.

→
04

EXECUTION GATEWAY

Separate verdict from execution.

Only explicitly allowed or resized actions can cross the execution boundary. BLOCK, REVIEW, and PAUSE verdicts do not execute.

FLIGHT RECORDER

Every verdict is inspectable.

Mandate, intent, evidence, policy checks, runtime findings, verdict, and runtime state are linked into a SHA-256 trace chain for tamper-evident replay.

FAIL CLOSED

Uncertainty is a control signal.

CIRCUIT is designed to fail closed when evidence is stale, prior settlement is uncertain, or runtime state is already PAUSED or EMERGENCY.

MCP SUPERVISOR

Agents can ask; policy still decides.

The MCP surface lets compatible AI hosts inspect state, submit typed intents for evaluation, and request trace briefings without exposing an execution tool.

CORE PRINCIPLE

Authorization is not a permanent safety guarantee.

Static permission says what an agent may access. CIRCUIT keeps asking whether the agent’s evolving behavior still matches the intent and assumptions under which that permission was granted.
